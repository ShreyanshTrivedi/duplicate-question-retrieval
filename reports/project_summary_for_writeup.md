## 3. System architecture (plain description)

1. **Preprocessing** (`src/preprocessing/clean.py`): lowercasing, punctuation
   stripping, NLTK `word_tokenize` tokenization, stopword removal (NLTK English
   stopword list), and Porter stemming. A `short_text_mode` flag (driven by
   `is_short_text`, threshold = 5 whitespace words) disables stopword removal
   and stemming for short text so it keeps surface tokens.
2. **Dual-space TF-IDF** (`src/retrieval/tfidf.py`): fits three independent,
   corpus-wide `TfidfVectorizer` spaces — "light" (short-mode tokens + word
   bigrams), "heavy" (long-mode/stemmed unigrams), and a character 3–5-gram
   space (`char_wb`). At query time, light and heavy rankings are always
   computed and fused; the character space is added only for short queries.
   Fusion uses the project's own RRF function.
3. **Dual-space BM25** (`src/retrieval/bm25.py`): same light/heavy split, two
   independent `BM25Okapi` indexes, fused the same way.
4. **Dense** (`src/retrieval/dense.py`): `sentence-transformers/all-MiniLM-L6-v2`
   embeddings (384-dim, L2-normalized), indexed in a FAISS `IndexFlatIP` (exact
   inner-product search). Corpus is optionally subsampled (`corpus_subsample:
   100000` in `config.yaml`) while force-keeping all eval queries' qrel
   documents so held-out evaluation stays answerable.
5. **Hybrid-RRF** (`src/retrieval/hybrid_rrf.py`): fuses BM25's ranked list
   with Dense's ranked list using Reciprocal Rank Fusion.
6. **Evaluation** (`src/evaluation/run_evaluation.py`,
   `run_segmented_evaluation.py`, `src/evaluation/metrics.py`): computes
   P@10, Recall@10, MAP@10, nDCG@10 against qrels, writes
   `comparison_table.csv`, `segmented_metrics.csv`, `pr_curve.png`, and
   `pr_curve_data.json`.
7. **UI** (`src/ui/app.py`, Streamlit): three tabs — Search, Performance
   Comparison, Precision-Recall Curve — described in the outputs section below.

## 4. RRF formula verification

Formula required: `RRF_Score(d) = Σ_{m∈M} 1/(k + r_m(d))`, k≈60.

Implementation (`src/retrieval/hybrid_rrf.py`):
```python
def reciprocal_rank_fusion(result_lists, top_k, rrf_k=60):
    rrf_scores = defaultdict(float)
    for results in result_lists:
        for rank_idx, (doc_id, _) in enumerate(results, start=1):
            rrf_scores[doc_id] += 1.0 / (rrf_k + rank_idx)
    ...
```
This matches exactly: default `k=60`, summation over each result list
(`m ∈ M`), each term `1/(k + rank)` with 1-indexed rank. Verified live during
this validation: for two toy lists where doc `a` ranks 1st and 2nd across the
two lists, computed score was `0.03252247488101534`, identical to
`1/61 + 1/62` to 1e-12. The same function is reused inside TF-IDF and BM25's
internal light/heavy/char fusion and inside the top-level `HybridRRFRetriever`
(BM25 + Dense) — one formula, three use sites.

## 5. Short-text bug arc (chronological, with before/after numbers)

All aggregate numbers below are the 400-query held-out set, k=10, in the order
P@10 / Recall@10 / MAP@10 / nDCG@10.

1. **Original bug.** Aggressive stopword removal + stemming collapsed short
   queries to 0–1 surviving tokens (e.g. "What is the google?" → `['googl']`,
   "How do I post here?" → `['post']`). 6 of 40 short eval queries (15%)
   collapsed this way. Because many unrelated documents reduced to the same
   1-dimensional TF-IDF vector, cosine similarity tied at exactly 1.0 across
   non-identical documents — a degenerate ranking. Pre-fix snapshot
   (`reports/comparison_table_before_fix.csv`): TF-IDF 0.1283 / 0.8198 /
   0.6642 / 0.7274; BM25 0.1345 / 0.8442 / 0.7013 / 0.7613; Dense 0.1738 /
   0.9659 / 0.9087 / 0.9431 (unaffected); Hybrid-RRF 0.1688 / 0.9498 / 0.8838
   / 0.9228.
2. **First fix — global light-mode.** Switched TF-IDF/BM25 to light
   preprocessing (no stopword removal/stemming) for all text, plus TF-IDF word
   bigrams and a char n-gram fallback. This removed the 1.0-tie degeneracy but
   was applied uniformly, including to long queries that were never affected
   by the collapse bug. Aggregate after this fix (`DECISIONS.md`): TF-IDF
   0.1158 / 0.7301 / 0.5517 / 0.6184; BM25 0.1323 / 0.8302 / 0.6920 / 0.7526;
   Hybrid-RRF 0.1673 / 0.9416 / 0.8643 / 0.9081 — i.e. TF-IDF/BM25 metrics
   *dropped* relative to the buggy baseline, because the drop in (i) reflects
   the loss of artificial 1.0-tie inflation rather than a new regression, per
   the qid=1182 spot-check (TF-IDF 4/33, BM25 8/33, Dense 8/33, Hybrid 9/33
   qrel hits in top-10 — lexical methods behaving sanely, just not inflated).
3. **Long-query overcorrection found via segmentation.** Segmenting queries by
   the 5-word threshold showed the global light-mode fix had been
   over-applied: long-query TF-IDF fell *below* its original aggregate
   behavior even though long queries were never part of the collapse bug.
   (Short-query-only metrics for this round, from `reports/gap_analysis.md`:
   TF-IDF short 0.1225 / 0.7087 / 0.5044 / 0.5887 — this specific
   short-segment figure is sourced from the project's own gap-analysis report,
   not independently re-run in this validation pass.)
4. **Second corrective fix — per-text scoping attempt.** Introduced
   `is_short_text()` with the `short_text_word_threshold` (default 5) to pick
   light vs. heavy preprocessing *per text*, applied inside one shared
   vectorizer/BM25 index. This restored long-query TF-IDF to roughly its
   original aggregate (`DECISIONS.md`: 0.1256 / 0.7949 / 0.6564 / 0.7148), and
   the full aggregate run (`reports/scoped_full_evaluation.log`) measured
   TF-IDF 0.1200 / 0.7574 / 0.6206 / 0.6784, BM25 0.1263 / 0.7873 / 0.6584 /
   0.7137, Hybrid-RRF 0.1660 / 0.9391 / 0.8489 / 0.8937 — but it regressed
   short-query retrieval badly, because short (light-mode, surface-form)
   queries and long (heavy-mode, stemmed) documents now shared one vocabulary
   space with mismatched tokens. Per `reports/gap_analysis.md`, the broken
   per-document scoped round measured short-query TF-IDF at 0.0700 / 0.4205 /
   0.2981 / 0.3508 (also sourced from the project's gap-analysis report, not
   independently re-run here).
5. **Vocabulary fragmentation diagnosis.** Concrete qrel inspection showed the
   root cause of step 4's short-query regression: a single shared vectorizer
   tokenized short queries as surface forms (e.g. `geographic`) and long
   duplicate documents as stems (e.g. `geograph`), plus query-only bigrams
   that never matched any document token — i.e., per-document conditional
   tokenization inside one vocabulary fragments vocabulary alignment rather
   than fixing it.
6. **Final solution — dual-space RRF fusion.** Replaced per-document
   conditional tokenization with two independent, corpus-wide lexical spaces
   per lexical method: "light" (surface forms + word bigrams, all documents
   indexed this way) and "heavy" (stopword-removed + stemmed, all documents
   indexed this way), plus a corpus-wide character 3–5-gram space used only
   for short queries in TF-IDF. Light/heavy/char rankings are fused per-query
   with the same RRF formula used for the top-level hybrid. This guarantees
   every vectorizer/BM25 index is internally consistent (every document
   tokenized the same way within that space), so there is no cross-tokenization
   mismatch. Final numbers are reported in sections 1 and 2 above
   (`reports/comparison_table.csv`, `reports/segmented_metrics.csv`), verified
   by direct execution in this validation pass (unit tests in
   `tests/test_short_text_bug.py`, live re-ranking of the original collapsing
   queries showing no more 1.0-tie degenerate scores, and manual re-derivation
   of the weighted aggregate from the segmented rows).

## 6. Required outputs and where they live

- **Search Interface** — `src/ui/app.py`, "Search" tab. Lets the user pick any
  of the 4 methods (TF-IDF, BM25, Dense, Hybrid-RRF) from a dropdown and see
  top-k ranked results with scores. Confirmed live: the Streamlit app starts
  cleanly and serves HTTP 200 with no errors in this validation pass.

## 7. Dataset description (real numbers, pulled from `data/processed/*` and `data/raw/questions.csv`)

- Raw Quora Question Pairs file (`data/raw/questions.csv`): **404,290** question
  pairs, of which **149,263** are labeled `is_duplicate=1`.
- Processed corpus (`data/processed/corpus.parquet`, deduplicated unique
  questions): **537,929** rows (`qid`, `question`).
- Qrels (`data/processed/qrels.parquet`, built bidirectionally from
  `is_duplicate=1` pairs): **298,526** `(query_id, doc_id)` rows, covering
  **149,650** unique query IDs with at least one qrel.
- Held-out evaluation queries (`data/processed/eval_queries.parquet`): **400**
  queries (`eval_query_count: 400` in `config.yaml`), of which the segmentation
  split found **40 short** (≤5 words) and **360 long** (>5 words).
- Dense embeddings cache (`data/processed/embeddings.npy` /
  `embeddings_ids.npy`): **100,000 × 384** matrix (matches
  `retrieval.corpus_subsample: 100000` in `config.yaml`), L2-normalized
  (confirmed: `||embedding[0]|| = 1.0`), computed with
  `sentence-transformers/all-MiniLM-L6-v2`.
